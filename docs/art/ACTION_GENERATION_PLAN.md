## 一、目标与边界

构建一套 **可独立加载、可替换、可验证授权** 的 GPT 龙娘桌宠动作包。CAH 本身已经有 Planner / Worker / Helper / Runner 状态；Sentinel 仅将已核验的机器状态投影为桌宠的 *表现状态*，不得创造第二套调度器或向 CAH 回写状态。

- 首要用途：使 `WAIT_USER` 主动求助、`ERROR/BLOCKED` 明确受阻、**父任务真正完成**后高兴庆祝；其余状态尽可能复用用户提供的原始 20 姿势，而非盲目扩图。
- 保留 ZipZipPipe 原角色设定。原始三张图集和新生成图须区分“原作素材”“AI 生成的衍生候选”“用户验收后可用版本”。
- 只开发 **Sentinel 自身的美术规范和独立素材包**；不占用、调用或修改 CAH 的 Runner、调度、Task Cell、MV 工作负载。
- 原角色与相应衍生美术按照项目所有者确认的 **CC BY-NC-SA 4.0** 处理：标明 ZipZipPipe、许可链接、来源及修改/AI 生成说明，禁止未经另外授权的商业使用。代码另行采用 AGPL-3.0-only，不以代码许可证覆盖美术。参见 [ASSET_LICENSE.md](../../ASSET_LICENSE.md)。
- 在明确做出素材公开决定前：**公开仓库只放清单/描述/哈希与安全的示意，不自动提交或随 AGPL EXE 捆绑第三方美术二进制**；用户可在自己的独立 Sprite Pack 内使用。
- 禁止把“候选已经生成”标记为“已验收/可发行”，也不能因子任务 `DONE` 就触发父任务 `COMPLETE` 的庆祝。

## 三、状态语义 → 动作组（与机器状态分离）

| 视觉动作组 | 对应情形 | 核心表演 | 通知语义 |
| --- | --- | --- | --- |
| `IDLE` | 无活动任务，系统健康 | 站立、眨眼 | 静默 |
| `THINKING` | Planner `WAKING/REPLANNING` | 看材料、托腮思考 | 静默 |
| `WORKING` | Worker 真正 `RUNNING`，或 Renderer 执行中 | 坐在电脑前工作 | 静默 |
| `AUTO_WAIT` | `WAIT_RESULT/WAIT_DEP/WAIT_BARRIER/WAIT_RESOURCE` 等，系统还能自动推进 | 坐下等待、偶尔看日志 | 静默 |
| `RECOVERING` | `WAIT_HELPER/WAIT_WORKER_HELPER`、已有恢复负责人 | 查记录、想办法、尝试修复 | 非紧急状态提示，不伪报“需用户” |
| `WAIT_USER` | 父任务 `NEED_USER` / `WAIT_USER`，等待 Foreground 人工答复 | **双手举 `NEED HELP` 牌，定期探头提醒** | 高优先级，仅相同问题通知一次 |
| `BLOCKED` | 阻塞，尚未确认为终止错误；与 Helper 已接管区别 | **趴卧但睁眼，还在等待解阻** | 展示阻塞原因 |
| `ERROR` | 严重错误或无法推进 | **完全趴卧、沮丧，翅膀垂下** | 故障通知 |
| `COMPLETE` | **父任务最终完成 / 明确验收** | **起飞、盘旋、举 √ 牌庆祝，最后降落** | 仅真实完成时通知 |
| `PAUSED` | 用户关闭 Sentinel 监控 | 安静睡眠/暂停，不再读 Git | 不通知 |
| `DISCONNECTED` | Git / 网络 / 身份认证读取失败 | 趴卧抬头，带断线标记；缓存状态标“已过期” | 首次失联提醒，不把过期数据当实时状态 |

`HANDOFF/ROTATING/CLEANING` 是暂态或内部生命周期，不新开永久动作组；使用眼神、纸张放下/抬起、短暂淡入淡出等过渡动作。特别注意 **备用 Runner 的 `READY_OFF` 是正常待命，不是 `ERROR`**。

**执行门槛修订：** AS-00 先完成 32 姿势源文件的轻量登记与统一角色约束，优先重点核查首批五组；AS-01/02/03/05 在 AS-00 后可以分别审查、独立验收，彼此不再形成串行等待。AS-04/06 亦可与首批制作并行。AS-07 才需要汇总各组，AS-08 最后封装。艺术素材未被逐组接受前，不可纳入对外发行包。

## 四、逐项生成计划（每一项都先复用、再决定是否生成）

### AS-00 · 基线审查与角色一致性锁定（下一项）

**不生成新图。** 取回已有原始图集与 v0.1 的三张候选，做 20+3+9（共32个）姿势索引接触表，人工检查角色比例、龙角、翅膀、尾巴、服装和轮廓。核对透明通道、哈希及当前 Crop 错位问题。确定不同姿势的落地锚点、显示尺寸和图集独立授权来源。

交付：`AS-00-baseline-contact.png`（私有/受控输出）、`AS-00-review.md`、统一角色参考约束、通过/退回决议及可复用姿势编号。**验收门槛：**用户能逐张辨认所有 32 张素材；来源区分、透明背景和主要特征无遗漏。通过后才开始 AS-01。

### AS-01 · `WAIT_USER`：举 NEED HELP 牌请求协助（最高优先）

已有 `wait_user_need_help.png` 早期候选和补充生成的 3 张对应姿势均尚未验收；以下是候选角色职责，**先审查、优先复用，不强制再生成新图**：
1. `wait_user_sign_raise`：把手边牌子抬到胸前至面前，略前倾，眼神请求协助。
2. `wait_user_sign_wave`：保留牌子和双角/尾巴，轻微晃牌或探头，保持同一身体尺度。
3. `wait_user_sign_hold`：复用现有候选，持续等待时主要姿势；`sign_lower` 默认用反向过渡而非画另一整张。

**验收：**160–240px 显示仍能识别“向人求助”；牌子文本必须准确读为 `NEED HELP`。若生成文字不稳定，出**空白牌面**，文字由 Sentinel 的图形层清晰叠加，不以错误英文凑数；始终与错误趴卧区分。只在 CAH 实际 `WAIT_USER` 时保持求助牌。

### AS-02 · `ERROR/BLOCKED`：龙娘趴卧（次优先）

已有早期 `error_prone.png` 候选 + 补充生成的 3 张对应姿势，均尚未验收；**先审查已有图，不强制再生成**：
1. `blocked_prone_watch`：趴卧、抬头睁眼、轻微焦急，尾巴仍能动，表示“卡住但未宕机”。
2. `error_prone_low`：完全趴卧、闭眼/半闭眼、翅膀低垂，作为真正 ERROR 的主姿势。
3. `recover_prone_lift`（必要时）：双手轻撑抬头准备恢复，用于 ERROR → RECOVERING，而不是又摔倒一次。

**验收：**桌面底部有自然接触感，头角/翅膀/尾巴无穿模和重复，不使用流血、真实受伤或死亡符号；`BLOCKED` 与 `ERROR` 通过眼睛及动作幅度可辨，且不混淆 R5 的安静睡觉姿势。

### AS-03 · `COMPLETE`：举 √ 牌开心盘旋

已有 `complete_flying_check.png` + 补充生成的 3 张飞行候选，均尚未验收；**优先用这些帧制作一次性 GIF，无须为了数量继续生成**：
1. `complete_takeoff`：双脚离开基准地线，双翼张开，手持 √ 牌向上飞。
2. `complete_bank`：轻微侧身转弯，单手举 √ 牌，尾巴与裙摆顺方向摆动；不应生成多余手臂/反向勾号。
3. `complete_hover_check`：使用现有候选作为主庆祝帧。
4. `complete_land`：下降并收翅准备返回 IDLE，可考虑利用既有站姿＋程序插值，若自然则不新画。

**运动优先用程序插值**：围绕角色重心做轻量椭圆/8字路径、浮动和小角度旋转，图像仅提供必要不同视角与动作关键帧；不要求靠数十张 AI 静帧模拟运动。**验收：**√ 符号方向正确、手与牌连贯、翅膀可信；不能把 Worker 子任务 `DONE` 误当整个项目成功。

### AS-04 · `THINKING/RECOVERING`：推理与诊断

先复用原始 W1/W3 读资料和托腮姿势，W2/W4 电脑工作姿势。**仅当画面表达不清时再补 1–2 张** `recover_checklist`（查看修复清单）及 `thinking_compare`（在纸张与电脑间对照）。**验收：**Helper 正在自动修复时看起来是“还在努力处理”，不举 `NEED HELP`，也不摔倒。

### AS-05 · `IDLE/WORKING/AUTO_WAIT`：原始动作复用优先

不预定生成张数。用现有 I1–I6 站姿、W1–W6 工作姿、R1–R8 休息姿制作完整覆盖表。必要时才提新增候选单。**验收：**20 个原始姿势都有明确 ID；连续工作/自动等待不能每次 30 秒 Git 轮询就跳一次大姿势；保留角色落地高度、身体尺寸和连续性。

### AS-06 · `PAUSED/DISCONNECTED`：睡眠与失联区别

优先复用 R5 睡眠和 R6 趴卧睁眼，**原则上不生成新图**。`PAUSED` 可有轻量 `Zzz` 特效；`DISCONNECTED` 由程序叠加“断线/最近成功同步时间”。**验收：**用户关闭监控后不继续轮询或重复通知；连接异常不能误报“系统工作正常”。

### AS-07 · 过渡动作与小动画组（前述素材验收后）

以 `工作→求助`、`求助→工作`、`报错→排障`、`完成起飞→盘旋→降落`、`待机→工作` 为最小完整链路。大多数用位置/缩放/角度/淡入淡出及眼部微动；若两张角色姿态明显不连贯，则**最多补 1–2 张必要过渡关键帧**。

**验收：**在 128、192、256px 三档预览中无白边、闪变、裁断；动画时长/持续循环/可中断/恢复有说明；高优先级 `WAIT_USER` 可安全打断普通工作动作。

### AS-08 · Sprite Pack v0.2 规范与最终美术验收

只在上面各组有用户通过证据后，归一化角色最大可视尺寸、姿势逐张裁切框、`anchor`（站姿脚底、趴姿腹部接地点、飞姿角色重心）、分组与事件动作、FPS/时长、切换条件、资源 fallback、生成来源/衍生说明和 SHA-256。

交付建议：`pack.json`、`poses/<action-id>.png`、`LICENSE-ART.md`、`ATTRIBUTION.md`、contact sheets、审美验收记录和离线/错误状态测试素材。**验收：**未提供完整包时 v0.0.1 仍能回退；没有通过验收的候选不装入正式包。**把包接入 WPF 播放器属于后续独立工程任务**，本轮不修改 UI 或已经发布的版本。

## 五、每张补图统一生成规范（Prompt 锁定）

每次必须同时给模型：① 用户原始完整人物参考；② 同组已验收的姿势；③ 本条动作独立描述。**优先做对现有姿势的定向编辑，避免仅靠文字重造角色。**

**不可漂移的身份特征：**
- Q 版大头小身体、淡紫色眼睛、银白至薰衣草紫渐变长发和标志性额前卷发；
- 白紫分节弯曲龙角，尖耳与佩饰、侧边编结花形饰与流苏；
- 白紫淡色膜翼、卷曲鳞状尾巴；复杂而统一的白紫蕾丝/花结/悬坠服装与鞋子；
- 温和的白、银、淡薰衣草配色，细致且干净的二次元立绘线条。每一帧须保持身份一致、角翼尾无额外增生。

**画面要求：**一个角色、正交近正面或允许的轻微转向、无背景、真实 RGBA 透明、完整角/翅膀/尾巴/裙摆/道具不出框、手指结构和拿牌方向正确。尽量统一大角色占画面比例，保留后期裁切空间；不得把棋盘格画成不透明背景。记录每张图的实际尺寸，分辨率建议目标原始高精源不低于 1024px 的主要角色包围盒长边，具体按一组内一致性调整而不是强迫所有宽高相同。

**反例拒绝清单：**角色脸型或服装换人、两条尾巴/多余手臂、左右角畸形、文字乱码、负空间存在边缘白晕/彩色噪点、透明背景缺失、压缩造成高频伪影、240px 下表意不清、裙摆/尾巴裁断。

**生成流程：**一轮只生成一个指定 `action-id` → 保存未改原始 PNG → 透明通道与尺寸检查 → 与相邻两帧做对照图 → 在 128/192/256px 看缩略 → 用户接受或要求重做 → 将最终版本状态从 `candidate` 变更为 `accepted`。不要一轮生成十几张然后让用户一口气验收。

## 六、Sprite Pack 元数据草案

**以下是建议接口，不是 v0.0.2 已支持的实际格式：**

```json
{
  "schema": "cah-sentinel.sprite-pack.v0.2-draft",
  "pack_id": "zipzippipe-gpt-dragon-girl",
  "software_license": "AGPL-3.0-only",
  "art_license": "CC BY-NC-SA 4.0",
  "author": "ZipZipPipe (original character)",
  "pose": {
    "id": "wait_user_sign_hold",
    "file": "poses/wait_user_sign_hold.png",
    "source_kind": "ai-generated-derivative",
    "approval": "candidate",
    "rect_px": [0, 0, 1122, 1402],
    "anchor_normalized": [0.5, 0.93],
    "scale_hint": 1.0,
    "sha256": "<hash after actual export>"
  }
}
```

`software_license` 仅是背景说明，**不会将美术授权重新定义为 AGPL**。生产版将把版权归属、素材原帖、修改说明、具体动作、场景内尺寸及循环/过渡映射分开列字段。真正的裁切与锚点数值必须在 AS-00 / AS-08 审查后测量，不能直接采纳示例的临时数值。
